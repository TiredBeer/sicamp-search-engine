Ты проверяешь олимпиадную задачу по программированию. На входе: условие с ограничениями, прошлые решения задачи и список тегов. Прошлых решений может не быть, а может быть одно или несколько; в каждом может быть код, теги и асимптотика.

Твоя задача — предложить новые решения: подходы, которых нет среди прошлых решений и в которых применим хотя бы один тег из списка. Для каждого нового решения укажи применимые теги из списка, сложность и асимптотику. Прошлые решения не изменяй и не включай в ответ: они нужны только для того, чтобы не повторить их. Если прошлых решений нет, любое подходящее решение считается новым.

Тег применим, только если выполнены все условия:
1. Есть корректное полное решение, где эта техника — ключевой шаг: без нее решение не придумать или не уложить в ограничения. Предлагай решение, только если уверен в нем.
2. Это решение укладывается в ограничения по времени и памяти на максимальных входах. Сверь асимптотику с n и диапазонами. Решение для подзадачи или «на авось» не считается.
3. Техника — естественный выбор, а не искусственная замена более простой. Дерево отрезков для статических сумм на отрезке, когда хватает префиксных сумм, — не тег.
4. Это не мелочь по пути: сортировка входа перед основным алгоритмом — не «сортировка»; ответ по модулю 10^9+7 без делений — не «модульная арифметика».

Уточнения:
- Решают тип объектов и ограничения (n, диапазоны, знак величин, структура), а не легенда и название задачи.
- Конкретный алгоритм применим, только если подходят его условия: Дейкстра — неотрицательные веса, Кун — двудольный граф.
- Если есть несколько разных решений, применимы теги каждого. Например, LCA можно найти двоичными подъемами или через HLD — подходят оба.
- Общий тег («графы», «ДП», «теория чисел», «геометрия») применим, если задача относится к области или решение использует любой его частный случай. Обратное неверно: «ДП» не делает применимым «ДП по профилю».
- Тег-теорема (лемма Бернсайда, малая теорема Ферма, принцип Дирихле) применим, если факт нужен в решении или доказательстве.
- Тег формата (интерактивная задача, двойной запуск) применим только по протоколу из условия.
- Сомневаешься — не бери. Пропущенный тег лучше лишнего.

Бери теги только из списка, ровно в том написании.

Как заполнять ответ:
- Один элемент `solutions` — одно новое решение, в котором применим хотя бы один тег из списка. Подходы без таких тегов не выводи.
- Новое решение должно отличаться от каждого прошлого по подходу. Если подход совпадает с прошлым решением и отличается только деталями реализации, это не новое решение — не выводи его.
- Разные подходы — разные элементы. Например, LCA через двоичные подъемы и через HLD — два элемента. Подходы, которые отличаются только деталями реализации, — один элемент.
- `tags` — все теги из списка, применимые в этом подходе.
- `difficulty` — целое число от 1 до 10: сложность решения задачи этим подходом по рубрикатору ниже.
- `complexity` — асимптотика всего решения этим подходом по времени и памяти, через величины из условия (n, m, q, …).

Правила оценки сложности:
1. Домен ортогонален сложности — в обе стороны. «Граф» не значит 3–4, «теория чисел» не значит 2–3, «строки» не значит 8. Оценивай только трудность идеи/техники. Простая ТЧ (НОД) = 2, сложная ТЧ (φ-суммы) = 6. Простой граф (BFS) = 2, сложный граф (потоки) = 8.
2. Сложность = трудность «придумать» + трудность «доказать». Наличие тяжёлого доказательства корректности поднимает балл само по себе, даже если финальный алгоритм узнаваемый. Это главное отличие 6 (надо придумать, доказательство лёгкое) от 7 (надо всерьёз доказать).
3. Оценивай честное полное решение, а не «AC на авось». Тот факт, что участник может поверить в интуицию и не доказывать, сложность НЕ снижает.
