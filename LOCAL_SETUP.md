# Локальный запуск LKL: от репозитория до приложения

Инструкция для Windows и PowerShell. В результате будут работать три контейнера: `frontend`, `backend` и PostgreSQL с pgvector (`db`). Python, uv, Node.js и зависимости приложения устанавливаются внутри образов; для этого способа запуска они не нужны на компьютере.

## 1. Подготовить Docker и открыть репозиторий

Проверьте Docker Engine и Compose:

```powershell
docker version
docker compose version
```

В выводе `docker version` должна быть доступна часть `Server`. Используется команда `docker compose` (Compose V2).

## 2. Создать или проверить `.env`

Файл `.env` должен лежать рядом с `compose.yaml`. Создайте его из примера, если файла ещё нет:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
notepad .env
```

Если ключ уже добавлен, используйте существующий `.env`. Для полноценной работы с LLM проверьте следующие значения:

```dotenv
POSTGRES_PASSWORD=sicamp
SEED_DEMO=true
LLM_PROVIDER=auto
LLM_BASE_URL=https://llm-gateway.sicamp.ru/v1
LLM_API_KEY=сюда_вставить_свой_ключ
LLM_MODEL=nebius/Qwen/Qwen3-235B-A22B-Instruct-2507
EMBEDDING_PROVIDER=local
EMBEDDING_LOCAL_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
EMBEDDING_DIMENSIONS=384
EMBEDDING_THREADS=2
```

Сохраните файл. Пример выше показывает настройки: вместо строки `сюда_вставить_свой_ключ` нужен действующий ключ лагеря. `.env` исключён из Git.

При `LLM_PROVIDER=auto` наличие ключа включает реальную LLM. Без ключа включается деморежим: доступны просмотр и поиск, но полноценный анализ через LLM и CLI-импорт с анализом требуют ключа.

`SEED_DEMO=true` добавляет восемь демонстрационных задач при запуске пустой базы. Если нужен изначально пустой банк, установите `SEED_DEMO=false` до первого запуска. Данные уже существующей базы сохраняются в Docker volume.

## 3. Собрать и запустить все контейнеры

Из корня репозитория выполните:

```powershell
docker compose up -d --build
```

Первый запуск требует Интернета: Docker скачивает образы и зависимости. Сборка может занять несколько минут. Команда запускает контейнеры в фоне.

Условия запуска: Docker Desktop работает, порты `3000` и `8000` свободны. PostgreSQL доступен другим контейнерам и не публикует порт на компьютер.

## 4. Убедиться, что приложение готово

```powershell
docker compose ps
```

Ожидаемый результат:

| Сервис | Состояние |
|---|---|
| `db` | `Up ... (healthy)` |
| `backend` | `Up ... (healthy)` |
| `frontend` | `Up ...` |

Проверьте API через тот же адрес, который использует интерфейс:

```powershell
Invoke-RestMethod http://localhost:3000/api/health
Invoke-RestMethod http://localhost:3000/api/stats
```

В ответе `/api/health` должны быть `status: ok`, `llm_provider: gateway`, `llm_configured: true`, `embedding_provider: local` и `semantic_search: true`. Последний запрос показывает количество задач и решений в текущей базе. Проверка health подтверждает конфигурацию LLM; реальный вызов модели выполняется при добавлении или переиндексации задачи.

Локальная модель эмбеддингов скачивается при первом обращении к ней и сохраняется в volume `embedding_models`. Поэтому первый поиск или добавление задачи может занять больше времени даже при статусе `healthy`. Последующие обращения используют кэш.

## 5. Открыть приложение и проверить основные действия

Откройте в браузере:

- **Приложение:** http://localhost:3000
- **Swagger с методами API:** http://localhost:8000/docs

Для первого знакомства:

1. На странице поиска введите, например, `сумма на отрезке`. Откройте найденную задачу, посмотрите условие и решения.
2. Попробуйте фильтры тегов и сложности, затем сбросьте их.
3. Нажмите кнопку добавления задачи. Укажите название и полное условие, включая ограничения. Для небольшого примера подойдёт задача о сумме массива из `n` целых чисел, где `1 ≤ n ≤ 100000` и `|a[i]| ≤ 10^9`.
4. Сохраните задачу. При настроенной LLM она получит структурированное описание и предложенные решения. В карточке решения можно посмотреть идею, асимптотику времени и памяти, сложность и отметку генерации LLM.
5. Если есть исходный код, передайте его при добавлении задачи или добавьте решение через интерфейс. Проверьте просмотр кода и редактирование решения.

Добавление задачи и переиндексации с анализом обращаются к реальной LLM и расходуют её квоту. Обычный поиск с локальными эмбеддингами выполняется на CPU без обращения к LLM Gateway.

## 6. При необходимости загрузить несколько задач Timus

Этот шаг необязателен. CLI можно запустить в Docker, используя папку на компьютере. Все команды ниже выполняются из корня репозитория.

Сначала проверьте файлы без загрузки и без вызова LLM:

```powershell
$timusFolder = "C:\Users\pc\Downloads\drive-download-20261118T143427Z-1-001\timus-master"
docker compose run --rm --no-deps -v "${timusFolder}:/imports:ro" backend /app/.venv/bin/python -m app.import_timus /imports --api-url http://backend:8000 --ids 1007 1013 1029 --limit 3 --dry-run
```

Затем загрузите только эти три задачи:

```powershell
docker compose run --rm --no-deps -v "${timusFolder}:/imports:ro" backend /app/.venv/bin/python -m app.import_timus /imports --api-url http://backend:8000 --ids 1007 1013 1029 --limit 3
```

На текущей локальной базе эти задачи уже импортированы: команда выведет `skipped`. На новой базе они будут добавлены с анализом через LLM. Исходная папка подключается только для чтения.

Повторный запуск пропускает успешно импортированные задачи. Без `--ids` и `--limit` CLI обработает всю папку. Остальные параметры и правила импорта описаны в [README](README.md#импорт-папки-timus-через-cli).

## 7. Остановить приложение и вернуться к нему позже

Для остановки с сохранением контейнеров:

```powershell
docker compose stop
```

Повторный запуск:

```powershell
docker compose up -d
```

Можно также остановить и удалить контейнеры, сохранив базу и кэш модели:

```powershell
docker compose down
```

Для следующего запуска снова используйте `docker compose up -d`. Данные хранятся в volumes `postgres_data` и `embedding_models`. Не добавляйте `-v` к `down`, если хотите сохранить базу и кэш модели.

## 8. Применить изменения кода или `.env`

После получения изменений репозитория или редактирования настроек выполните из его корня:

```powershell
docker compose up -d --build
```

Если сменили модель эмбеддингов с сохранением размерности, запустите пересчёт поискового индекса через экран управления банком задач. Для изменения размерности используйте отдельную инструкцию в [README](README.md#режимы-работы-и-модели).

## 9. Если запуск не удался

**Не удаётся подключиться к Docker Engine / нет `dockerDesktopLinuxEngine`.** Запустите Docker Desktop, дождитесь готовности движка, затем повторите команду запуска. Проверьте, что выбран режим Linux-контейнеров.

**Контейнер не становится `healthy`, приложение не открывается или API возвращает 502.** Посмотрите состояние и последние сообщения:

```powershell
docker compose ps
docker compose logs --tail 100 backend
docker compose logs --tail 100 db
docker compose logs --tail 100 frontend
```

Если backend работает напрямую на http://localhost:8000/api/health, а через http://localhost:3000/api/health недоступен, перезапустите прокси:

```powershell
docker compose restart frontend
```

**Порт `3000` или `8000` занят.** Остановите другое приложение, которое занимает этот порт, либо измените левую часть соответствующей привязки `ports` в `compose.yaml` и используйте новый адрес в браузере.

**Поиск сообщает, что модель эмбеддингов изменилась.** Запустите пересчёт поискового индекса через интерфейс управления банком. Такая переиндексация использует эмбеддер и не вызывает анализ задач через LLM.

**Ошибка ключа, квоты, HTTP 502 или тайм-аут от LLM Gateway.** Проверьте `LLM_API_KEY` и выбранную модель в `.env`, примените настройки командой из шага 8. При временной ошибке повторите действие после восстановления Gateway; для фоновых заданий сначала проверьте их состояние в интерфейсе. При ошибке импорта можно повторить ту же CLI-команду: успешно сохранённые задачи будут пропущены.

**PostgreSQL сообщает об ошибке пароля после изменения `.env`.** Пароль существующей базы хранится в volume и не меняется от редактирования `POSTGRES_PASSWORD`. Для доступа к этой базе верните в `.env` прежний пароль и пересоздайте backend командой из шага 8.
